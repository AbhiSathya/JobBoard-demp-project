Problem · Users · Objective

Matching people to jobs is a search problem disguised as a form.

Candidates describe what they want in a sentence, not a filter panel. Admins need to know an applicant is real before they read the résumé. This project builds a job board where that sentence becomes a ranked, explained shortlist.

Company Admin

  • Post and manage job listings, open or closed
  • Review applicants against the job, not a resume pile
  • Move candidates through Applied → Shortlisted → Rejected
  • See real numbers — applications, skills, pipeline — on one dashboard

Candidate

  • One saved profile — skills, education, projects, preferences
  • Search and filter the open roles directly
  • Or just describe the job in plain English and get a ranked, explained shortlist
  • Apply in one click with the saved profile

AI Matching — Approach & Limits

Ranking is a weighted sum, not a prompt.

The brief's own constraint: don't bury essential ranking logic inside something untestable. So the LLM only does the part it's good at — reading a sentence — and a fixed, unit-tested scorer does the ranking.

What runs where

  • LLM (optional): parses free text into structured intent — 8s timeout
  • Deterministic fallback: keyword extraction, runs the whole demo if the key is absent, times out, or the response is malformed
  • Scorer: pure Python, no I/O, 25 unit tests pin the weights and ranking order
  • Explanation: assembled from the score breakdown's own fields — cannot state a skill or fact that isn't real

Limitations: skill/domain matching is exact-keyword, not semantic. Next: embedding similarity for the fallback path; weights learned from real outcomes instead of hand-set.
